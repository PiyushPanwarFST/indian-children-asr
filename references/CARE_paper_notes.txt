========================================================================
WHAT CARE DOES (Speech Emotion Recognition, NOT ASR)
========================================================================

CARE is a self-supervised dual encoding scheme for Speech Emotion
Recognition (SER). It is NOT an ASR model. It has:

  1. A SEMANTIC encoder — aligns speech with text (RoBERTa embeddings)
  2. An ACOUSTIC encoder — predicts frame-level PASE+ acoustic features
  3. A COMMON encoder (shared) — 6 WavLM-base transformer layers

CARE achieves state-of-the-art SER across 8 diverse emotion datasets
with only 160M parameters (beats SALMONN-13B which has 80x more params).


========================================================================
CARE ARCHITECTURE (from Fig. 2, page 4)
========================================================================

  Audio waveform
       ↓
  Convolutional Feature Extractor (from WavLM)
       ↓
  COMMON ENCODER (6 transformer layers, WavLM-base init)
       ↓                              ↓
  ┌─────────────────┐     ┌──────────────────────────┐
  │ ACOUSTIC ENCODER │     │    SEMANTIC ENCODER       │
  │ 6 transformer    │     │ 6 transformer layers      │
  │ layers (WavLM)   │     │ (initialized from RoBERTa)│
  │ + FC layer       │     │ TRANSFORMERS FROZEN        │
  │ (768→256)        │     │ Conv adapters TRAINED      │
  │                  │     │ (1D conv before & after    │
  │ Trained with     │     │  each transformer layer)   │
  │ FRAME-LEVEL MSE  │     │                            │
  │ vs PASE+ targets │     │ Trained with UTTERANCE-    │
  │                  │     │ LEVEL MSE vs RoBERTa       │
  │ y_pase (256-dim) │     │ mean-pooled embeddings     │
  └─────────────────┘     │ y_text (768-dim)           │
                           └──────────────────────────┘

  For downstream (SER classification):
    - Layer outputs from all 13 layers are extracted
      (1 conv + 6 common + 6 semantic/acoustic concatenated)
    - CONVEX COMBINATION with learned per-layer weights
    - Mean-pool across time → single 1536-dim vector
    - 2-layer classification head (FFN)
    - Only convex weights + classification head are trained


========================================================================
CARE's FUSION: CONVEX COMBINATION (NOT Gated Fusion)
========================================================================

CARE does NOT use Gated Multimodal Units or sigmoid gating.

CARE's fusion is a CONVEX COMBINATION of layer representations:

    output = Σ(w_i * layer_i)    for i = 1..13 layers
    where: Σ(w_i) = 1,  w_i ≥ 0  (convex constraint)

  - 13 scalar weights total (one per layer)
  - Weights are shared across all frames and all feature dimensions
  - Weights are task-specific (learned per downstream dataset)
  - After combination: mean-pool across time → 1536-dim vector

This is much simpler than our approach:
  - CARE: 13 scalar weights (per-layer)
  - Ours: per-frame, per-dimension sigmoid gate (~1.18M parameters)


========================================================================
HOW OUR APPROACH RELATES TO CARE
========================================================================

What we took from CARE (the concept):
  1. Dual-encoder idea: two specialized encoders, one semantic, one acoustic
  2. Knowledge distillation: each encoder learns from a different teacher
  3. Freezing encoders during downstream training

What is DIFFERENT in our approach:
  1. TASK: We do ASR (sequence prediction), CARE does SER (classification)
  2. FUSION: We use Gated Multimodal Units (Arevalo 2017), not convex combination
  3. ARCHITECTURE: We have two SEPARATE Whisper encoders, CARE has a
     SHARED common encoder with branching
  4. SEMANTIC TEACHER: CARE uses RoBERTa (TEXT model), we use IndicConformer
     (SPEECH model). This is why CARE's two branches are more complementary.
  5. ACOUSTIC TEACHER: CARE uses PASE+ (low-level acoustic features),
     we use Kid-Whisper (children's speech model)
  6. OUTPUT: CARE mean-pools to utterance level, we keep frame-level for CTC

IMPORTANT INSIGHT FROM CARE:
  CARE's semantic encoder uses a TEXT model (RoBERTa) as teacher.
  This is exactly our proposed Direction 2 (MuRIL integration).
  CARE proved that text→speech knowledge distillation works.
  Table V (page 8): removing RoBERTa init drops performance on ALL datasets.

  Our current semantic branch uses IndicConformer (speech model) as teacher,
  making it redundant with the acoustic branch. Switching to MuRIL (text model)
  would make our approach more similar to CARE's design philosophy.


========================================================================
CARE's FREEZING STRATEGY (Table V ablation, page 8)
========================================================================

In the semantic encoder:
  - Transformer layers: FROZEN (initialized from pre-trained RoBERTa)
  - Convolutional adapters: TRAINED (bridge speech→text representations)

  Ablation results (Table V):
    CARE (full):      best performance across all datasets
    CARE-No init:     random init instead of RoBERTa → performance drops
    CARE-Trans:       update RoBERTa transformers → performance DECREASES
    CARE-FT:          update everything → performance decreases

  Key finding: Updating the RoBERTa transformer layers HURTS performance.
  The pre-trained text representations should be preserved (frozen).
  Only the convolutional adapters should be trained to align speech→text.

In the acoustic encoder:
  - All layers trained (not frozen)
  - Initialized from WavLM-base

In the common encoder:
  - All layers trained during pre-training
  - Initialized from WavLM-base
